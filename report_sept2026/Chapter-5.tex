\chapter{CONCLUSION AND FUTURE WORK}
\label{chap:conclusion}

\section{Conclusion}
\label{sec:conclusion}
This project set out to make the number of Householder factors in DeltaProduct per-token and learned, and to establish how many factors each token requires. The base method was reproduced on $S_3$ and $S_5$, matching the published behaviour.

The analysis showed that a token's requirement is set by the cheapest faithful representation of the group generated by the whole alphabet, not by the token: a 5-cycle requires four factors when the closure is $S_5$ and two when it is $A_5$, and alphabets generating $A_5$ are learned with two factors. With an allocation derived from this analysis, per-token order matches the four-factor model at 2.3 to 3.5 times fewer factors per token. The learned halting gate separated the requirement classes in 7 of 49 runs, never under-allocating a token or reducing accuracy; its best runs need 2.20 factors per token at a token accuracy of 0.9998, and one reached the exact allocation of 1.30. On the Boxes entity-tracking dataset, a DeltaProduct layer applied state updates that attention of the same size did not (0.968 against 0.312 exact match after one operation).

Two limitations define the next phase: training is bistable, so the fraction of runs that succeed is now the main limitation of the mechanism, and the savings are in required factors per token, since every factor is still executed.

\section{Future Work}
\label{sec:future}
\begin{enumerate}[label={(\arabic*)}]
	\item \textbf{Reliability of the learned gate.} Compare the earliest gate configuration, which reached the exact allocation, with later ones one change at a time to find what raised the floor to two factors, and measure the success fraction over enough repeated runs to give narrow confidence intervals.
	\item \textbf{Realised efficiency.} Execute only the allocated factors, for example with a per-level capacity router in the spirit of Mixture-of-Depths \cite{mod} that keeps tensor shapes static, and measure training and inference time against fixed orders at equal accuracy.
	\item \textbf{Multi-level requirements.} Evaluate the gate on alphabets whose requirement takes every value from 1 to 4, and test whether it learns that a 5-cycle requires two factors under an $A_5$ alphabet but four under an $S_5$ one.
	\item \textbf{The high-requirement regime.} Test the removal of the additive input pathway \cite{howe} on the configuration with 96\% maximum-requirement tokens, which remains unresolved.
	\item \textbf{Adaptive order in natural language.} Train DeltaProduct on Boxes at $\nh = 1$, 2 and 3 to establish whether the task needs more than one factor, then train the halting gate on it and test whether operation tokens, and moves in particular, receive more factors than description tokens; extend the evaluation to SCONE \cite{scone}, ProPara \cite{propara} and NPN-Cooking \cite{npncooking}. A router between attention and recurrence is not pursued, since neither task showed an advantage for attention that mixing could combine.
\end{enumerate}
